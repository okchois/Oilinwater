# RS-485 기본 출력 + 부트로더 펌웨어 업데이트 설계

작성일: 2026-09-26 · 상태: 설계안 v0.1 (참조 구현 포함)

## 0. 결정 사항

| 항목 | 결정 |
|---|---|
| 기본 출력 | **RS-485 Modbus RTU + 아날로그 2채널(채널별 전압/전류 선택)** (둘 다 기본 탑재, 2026-09-26 확정). 회로: [hw/hardware-block-design.md](hw/hardware-block-design.md) |
| 펌웨어 업데이트 | **상주 부트로더**가 같은 RS-485 라인과 같은 슬레이브 주소로 Modbus RTU를 통해 업데이트 수신 |
| 센서 소자 | **IST AG MK 계열** (현재 공급 중) |

## 1. 제품 구조 (EE364형 일체형)

```
 [보호캡: 슬롯/홀형 SUS, 교체형]─[센서 소자 + Pt1000]─[G½" ISO 228 나사 + 본디드 씰]─[육각]─[원통 SUS 하우징: 전자부]─[M12 5핀 A-code]
```

- 접액부: SUS316L, 씰 FKM(에스테르유/인산에스테르는 EPDM·FFKM 옵션)
- 전자부 하우징: SUS304/316, 레이저 마킹 라벨(모델명, 출력, 전원, 온도범위)
- 커넥터: **M Connect 사용** — 아래 핀 배치는 M12 5핀 A-code (IEC 61076-2-101) 기준 안이며, 사용 중인 M Connect 품번(크기·핀 수·코딩)에 맞춰 확정
- 센서: IST AG MK 계열 정전용량 소자(공급 중) + Pt1000, 한 보호캡 안에 열적으로 결합
- PCB: 원통 하우징에 맞춘 세로형 2단(센서 측정 보드 / 전원·통신 보드) 권장

### 1.1 커넥터 핀 배치(안) — M Connect 8핀

아날로그 2채널과 RS-485를 모두 기본으로 탑재하므로 8핀을 씁니다. EE364 호환안은 다음과 같습니다.

| 핀 | 신호 |
|---|---|
| 1 | NC |
| 2 | RS485 B (D−) |
| 3 | RS485 A (D+) |
| 4 | OUT1 (전압/전류 선택) |
| 5 | OUT2 (전압/전류 선택) |
| 6 | GND (공통) |
| 7 | NC (오결선 보호를 위해 미연결) |
| 8 | V+ 12–30 V DC |

> 핀 배치는 M Connect 품번 확인과 EE364 원문 대조를 거쳐 확정합니다. 상세 내용은 [하드웨어 블록 설계](hw/hardware-block-design.md) 3절에 있습니다.

### 1.2 참고: E+E EE364 핀맵 (원문 확인)

Quick Guide v3.7 원문으로 확인했습니다. 8핀 표준형은 2: RS485 B, 3: RS485 A, 4: OUT1, 5: OUT2, 6: GND, 8: V+이고, 1, 7번은 쓰지 않습니다. 이는 1.1절의 우리 안과 일치합니다. OEM형(RS485 전용 5핀)과 Modbus 맵은 [EE364 원문 요약](reference/ee364-summary.md)에 있습니다.

주의:
- EE364의 공장 설정은 9600 bps 8E1, 주소 243이고, FLOAT32는 하위 워드 먼저(CDAB)입니다. 우리 기본값(19200 8E1, 주소 1, ABCD)과 다릅니다.
- EE364 호환 모드를 넣으면 앱의 레지스터 0x0000(모드 ID)이 EE364의 "Modbus 주소" 레지스터와 충돌합니다. 모드 ID를 0xFF00 등으로 옮겨야 합니다(요약 문서 5절).

## 2. RS-485 하드웨어

| 항목 | 설계 |
|---|---|
| 트랜시버 | 절연형 권장 (ADI ADM2587E, TI ISO1410 + 절연 DC/DC) 또는 비절연 저가형(THVD1450 등) + 옵션 |
| 방향 제어 | MCU USART 하드웨어 DE 출력(STM32 `DEM`) 사용 → 소프트웨어 타이밍 오류 제거 |
| 보호 | 버스 라인 TVS(SM712 등), 직렬 PTC/저항, 전원 역극성 보호, 서지 IEC 61000-4-5 |
| 페일세이프 | 내장 페일세이프 트랜시버 사용. 종단 120 Ω는 **내장하지 않음**(버스 끝단에서 외부 설치) |
| 전원 | 12–30 V DC, 소비전류 < 20 mA @24 V 목표 |
| 통신 기본값 | 주소 1, **19200 bps, 8E1** (Modbus 표준 기본), 설정 가능 9600–115200, N/E/O |

## 3. 메모리 맵 (예: STM32L4 256 KB, 2 KB 페이지)

| 주소 | 크기 | 영역 | 업데이트 시 |
|---|---|---|---|
| 0x0800_0000 | 32 KB | **부트로더** (쓰기 보호 WRP) | 변경 안 함 |
| 0x0800_8000 | 208 KB | **앱 슬롯**: 헤더 512 B + 앱(벡터 테이블부터) | 소거·재기록 |
| 0x0803_C000 | 8 KB | 설정 (주소, 통신 속도, 오일 계수 등, A/B 2중화) | 유지 |
| 0x0803_E000 | 8 KB | **공장 교정 데이터** (센서 교정 계수, 시리얼번호) | **절대 소거 안 함** |

- 앱은 `0x0800_8200`에 링크합니다. 헤더 512 B 덕분에 VTOR 정렬 요구가 충족됩니다.
- 교정 데이터를 앱 슬롯 밖에 두므로, 펌웨어를 업데이트해도 **교정값이 보존**됩니다.
- 부트로더와 앱은 설정 영역의 주소·통신 속도를 **같이** 읽습니다. 그래서 업데이트할 때 통신 설정을 바꿀 필요가 없습니다.
- 호스트 시뮬레이터는 편의상 슬롯을 96 KB로 설정했습니다(`main_host.c`).

## 4. 부팅 흐름

```
리셋
 └─ 부트로더 시작
     ├─ 설정 영역에서 주소/속도 로드 (손상 시 기본값: 주소 1, 19200 8E1)
     ├─ 부트 요청 플래그 확인 (RTC 백업 레지스터 또는 .noinit RAM 매직값) → 있으면 지우고 [부트로더 대기]
     ├─ 앱 유효성 검사: 헤더 magic/CRC, hw_id, 앱 CRC-32 → 무효면 [부트로더 대기]
     └─ 유효하면 앱으로 점프
[부트로더 대기]
     └─ Modbus 요청 처리 (BEGIN → DATA × N → FINISH → RUN)
         RUN: 응답 송신 완료 후 → 주변장치 정지, VTOR = 0x0800_8200, MSP 설정, 리셋 벡터 점프
```

**앱 → 부트로더 진입:** 앱은 홀딩 레지스터 `0x1000`에 `0xB007`이 쓰이면 먼저 정상 응답을 보냅니다. 송신이 끝나면 부트 요청 플래그를 세팅하고 `NVIC_SystemReset()` 합니다.

**복구성:** 부트로더는 업데이트 경로로 절대 지워지지 않습니다. 업데이트 중 전원 차단이나 통신 끊김이 생겨도 다음 부팅 때 부트로더에 머물기 때문에, RS-485로 다시 업데이트하면 복구됩니다. 현장에 가서 분해할 필요가 없습니다.

## 5. 이미지 형식 (.oiw)

`[헤더 512 B] + [앱 바이너리]`. 헤더 정의는 `firmware/common/fw_image.h`에 있고, 모든 필드는 리틀엔디언입니다.

| 오프셋 | 필드 | 설명 |
|---|---|---|
| 0 | magic | `0x4657494F` ("OIWF") |
| 4 | hdr_version | 1 |
| 6 | hw_id | 하드웨어 식별자. 다른 보드용 이미지 차단 |
| 8 | fw_version | `0x00MMmmpp` |
| 12 | payload_size | 앱 크기 |
| 16 | payload_crc32 | 앱 CRC-32 (IEEE, zlib 호환) |
| 20 | load_addr | 슬롯 시작 + 512 |
| 24 | reserved[36] | 0 (향후 서명·최소 버전 등) |
| 60 | hdr_crc32 | 0–59 바이트의 CRC-32 |
| 64–511 | 0xFF 패딩 | |

## 6. 부트로더 Modbus 레지스터 맵

공통 규칙:
- 32비트 값은 **상위 워드 먼저**, 레지스터 안에서는 상위 바이트 먼저(Modbus 표준)입니다.
- 브로드캐스트(주소 0)에는 응답하지 않습니다.

### 6.1 정보 (FC03 읽기, 0x0000–0x000B)

| 주소 | 이름 | 설명 |
|---|---|---|
| 0x0000 | ID | **`0x424C` ("BL")** — 앱 모드에서는 `0x4150` ("AP"). 도구가 이 값으로 모드를 판별 |
| 0x0001 | BL_VERSION | 부트로더 버전 (0x0100 = 1.0) |
| 0x0002 | HW_ID | 하드웨어 ID |
| 0x0003 | STATE | 0 대기, 1 수신 중, 2 완료(검증됨), 3 오류 |
| 0x0004 | ERROR | 마지막 오류 코드 (6.4) |
| 0x0005 | BLOCK_SIZE | 128 |
| 0x0006–07 | MAX_SIZE | 슬롯 크기 (헤더 포함) |
| 0x0008 | NEXT_BLOCK | 다음에 받을 블록 번호 (재동기화용) |
| 0x0009 | APP_VALID | 설치된 앱 유효 여부 |
| 0x000A–0B | APP_VERSION | 설치된 앱 버전 |

### 6.2 명령 (0x0010)

| 명령 | 코드 | 전송 방법 | 동작 |
|---|---|---|---|
| BEGIN | 1 | FC16 `0x0010` × 3: [1, 크기 상위, 크기 하위] | 크기 확인 → 앱 슬롯 전체 소거 → 수신 시작 (최대 수 초 소요) |
| FINISH | 2 | FC06 `0x0010` = 2 | 모든 블록 수신 확인 → 앱 CRC 검증 → **헤더를 마지막에 기록** → 재검증 |
| RUN | 3 | FC06 `0x0010` = 3 | 앱 유효 시 응답 후 앱으로 점프 |
| ABORT | 4 | FC06 `0x0010` = 4 | 수신 중단 (앱은 무효 상태로 남음) |

### 6.3 데이터 (0x0100)

- FC16 `0x0100`, 수량 = 1 + ⌈n/2⌉ (최대 65 레지스터)
  - 첫 레지스터는 블록 번호(0부터), 나머지는 이미지 바이트 n개(최대 128)입니다. 홀수 바이트이면 0xFF로 패딩합니다.
- **블록 번호 = 이미지 오프셋 / 128.** 블록은 순서대로만 받습니다.
- **직전 블록의 재전송은 허용합니다.** 내용이 같으면 성공으로 응답하므로, 응답이 유실돼도 마스터는 같은 블록을 그대로 재시도하면 됩니다.
- 블록 0 수신 즉시 헤더를 검증합니다(magic, CRC, hw_id, 크기). 다른 보드용 이미지는 바로 거부합니다.
- 헤더 영역(첫 512 B)은 RAM에 모아 두었다가 FINISH 때 기록합니다.

### 6.4 오류 코드 (0x0004)와 Modbus 예외

| 코드 | 의미 | 예외 |
|---|---|---|
| 1 | 상태 오류 (예: BEGIN 없이 DATA) | 03 |
| 2 | 크기 오류 | 03 |
| 3 | 블록 순서 오류 | 03 |
| 4 / 5 | 플래시 소거 / 기록 실패 | 04 |
| 6 | 헤더 무효 | 03 |
| 7 | HW ID 불일치 | 03 |
| 8 | CRC 불일치 | 04 |
| 9 | 미완료 상태에서 FINISH | 03 |
| 10 | 재전송 블록 내용 불일치 | 03 |

### 6.5 업데이트 시퀀스

```
마스터                                           장치
 │ FC03 0x0000 ×1 ─────────────────────────────▶ │  "AP" (앱 실행 중)
 │ FC06 0x1000 = 0xB007 ───────────────────────▶ │  응답 후 리셋 → 부트로더
 │ FC03 0x0000 ×1 (폴링, ≤5 s) ────────────────▶ │  "BL"
 │ FC03 0x0000 ×12 (정보: HW_ID, 슬롯 크기) ──▶ │
 │ FC16 0x0010 [BEGIN, size] (타임아웃 10 s) ──▶ │  슬롯 소거
 │ FC16 0x0100 [i, data…] × N (재시도 3회) ────▶ │  순차 기록 + 읽기 검증
 │ FC06 0x0010 = FINISH ───────────────────────▶ │  CRC 검증 → 헤더 기록
 │ FC06 0x0010 = RUN ──────────────────────────▶ │  앱 실행
```

### 6.6 전송 시간 추정 (앱 100 KB, 800 블록)

- 요청 139 B + 응답 8 B이고, 문자당 11비트(8E1)입니다.

| 속도 | 블록당 | 총 |
|---|---|---|
| 19200 bps | 약 95 ms | **약 76 s** |
| 115200 bps | 약 17 ms | **약 14 s** |

- 다중 드롭 버스에서도 대상 주소 장치만 부트로더로 들어가므로, 다른 장치의 통신에는 영향이 없습니다(업데이트 중에는 버스를 점유).
- 향후 옵션으로, 업데이트할 때만 115200으로 올리는 `SET_BAUD` 명령을 검토합니다.

## 7. 앱 Modbus 레지스터 맵(초안)

32비트 float는 IEEE-754이고, 상위 워드 먼저(ABCD)입니다. 측정값은 FC03/FC04 둘 다 읽을 수 있게 합니다.

| 주소 | 이름 | 형식 | R/W |
|---|---|---|---|
| 0x0000 | ID "AP" (0x4150) | u16 | R |
| 0x0001–02 | FW 버전 | u32 | R |
| 0x0003 | HW ID | u16 | R |
| 0x0004–05 | 시리얼 번호 | u32 | R |
| 0x0100–01 | aw (0–1) | float | R |
| 0x0102–03 | %RS | float | R |
| 0x0104–05 | 오일 온도 [°C] | float | R |
| 0x0106–07 | 수분 [ppm] | float | R |
| 0x0108 | 상태 비트 (센서 이상, 온도 범위 이탈, 포화 경고, 교정 만료 등; NE107 매핑) | u16 | R |
| 0x0200 | 슬레이브 주소 (1–247) | u16 | RW |
| 0x0201 | 통신 속도 코드 (0:9600, 1:19200, 2:38400, 3:57600, 4:115200) | u16 | RW |
| 0x0202 | 패리티/정지비트 (0:8N1, 1:8E1, 2:8O1, 3:8N2) | u16 | RW |
| 0x0203–04 | 오일 계수 A | float | RW |
| 0x0205–06 | 오일 계수 B | float | RW |
| 0x0207 | 필터 시상수 [s] | u16 | RW |
| 0x0210 | OUT1 측정값 할당 (0: aw, 1: %RS, 2: T, 3: ppm) | u16 | RW |
| 0x0211 | OUT1 출력 모드 (0: 4–20 mA, 1: 0–20 mA, 2: 0–10 V, 3: 2–10 V, 4: 0–5 V, 5: 1–5 V, 6: 0–1 V, 7: 꺼짐) | u16 | RW |
| 0x0212–13 | OUT1 하한 측정값 (출력 최소에 대응) | float | RW |
| 0x0214–15 | OUT1 상한 측정값 (출력 최대에 대응) | float | RW |
| 0x0216 | OUT1 이상 시 출력 (0: 하한 알람 ≤3.6 mA/0 V, 1: 상한 알람 ≥21 mA/+10%, 2: 마지막 값 유지) | u16 | RW |
| 0x0218–1E | OUT2 (OUT1과 같은 구조: 할당, 모드, 하한, 상한, 이상 시 출력) | – | RW |
| 0x0220 | 아날로그 출력 상태 비트 (채널별 단선, 과부하, 과열, 설정 오류) | u16 | R |
| 0x0221 | 출력 시험 모드 (0: 정상, 1: 고정값 출력 — 루프 점검용) | u16 | RW |
| 0x0222–23 | 시험 모드 출력값 [mA 또는 V] | float | RW |
| 0x0300 | 설정 적용/저장 명령 | u16 | W |
| **0x1000** | **부트로더 진입: 0xB007 쓰기** | u16 | W |

통신 설정 변경은 `0x0300` 적용 명령을 받은 뒤, 응답을 보내고 나서 반영합니다. 설정 도중 통신이 끊기지 않게 하기 위해서입니다.

## 8. 안전·신뢰성 설계

1. **원자적 유효화:** 헤더는 마지막에 기록합니다. 그 전에 중단되면 앱은 무효로 남고 부트로더에 머뭅니다.
2. **이중 무결성:** 헤더 CRC-32와 앱 CRC-32를 두고, 부팅할 때마다 검증합니다(MCU HW CRC 유닛 사용 시 수 ms).
3. **HW ID 확인:** 다른 모델이나 보드 리비전용 이미지를 차단합니다.
4. **부트로더 보호:** 부트로더 영역은 쓰기 보호(WRP)합니다. 양산품은 읽기 보호(RDP Level 1)를 적용합니다.
5. **교정·설정 보존:** 앱 슬롯과 분리된 페이지에 두어 업데이트해도 소거되지 않습니다.
6. **워치독:** 앱과 부트로더 모두 IWDG를 사용합니다. 부트로더는 대기 중에도 워치독을 갱신합니다.
7. **향후 강화:** 이미지 서명(Ed25519 또는 ECDSA P-256, `reserved` 필드 대신 서명 섹션 추가), 최소 버전으로 다운그레이드 방지, 플래시 여유가 생기면 A/B 슬롯으로 자동 롤백.

## 9. 참조 구현 (저장소)

| 경로 | 내용 |
|---|---|
| `firmware/common/crc.[ch]` | Modbus CRC-16, CRC-32 |
| `firmware/common/fw_image.h` | 이미지 헤더 정의 |
| `firmware/bootloader/bl_core.[ch]` | **MCU 비의존 부트로더 코어**: Modbus RTU 처리 + 업데이트 상태 머신 |
| `firmware/bootloader/bl_port.h` | MCU 포트가 구현할 플래시 함수 3개 |
| `firmware/bootloader/port/host/main_host.c` | PC 시뮬레이터(RAM 플래시, NOR 쓰기 규칙 흉내, 앱 모드 에뮬레이션) |
| `tools/fwupdate.py` | 이미지 생성(`mkimage`), 정보(`info`), 업데이트(`flash`). pyserial 사용 |
| `tests/test_bootloader.py` | 통합 테스트 7종: 전체 업데이트, HW ID 거부, 재전송/순서, CRC 손상, 전원 차단 복구, 주소 필터, CRC 벡터 |

```bash
make -C firmware                               # 시뮬레이터 빌드
python3 -m unittest discover -s tests          # 테스트
python3 tools/fwupdate.py mkimage app.bin app.oiw --hw-id 1 --version 1.0.0
python3 tools/fwupdate.py flash app.oiw --port /dev/ttyUSB0 --addr 1 --baud 19200 --parity E
```

### 9.1 MCU 포팅 시 할 일

1. `bl_port.h`의 `bl_flash_erase/write/ptr`를 MCU 플래시 드라이버로 구현합니다(STM32L4: 페이지 소거 2 KB, 더블워드 기록).
2. USART 수신과 프레임 구분:
   - 수신 타임아웃 기능(`RTOF`, 3.5 문자)이나 IDLE 인터럽트로 프레임 끝을 검출합니다.
   - 검출되면 `bl_handle_frame()`을 호출합니다.
   - 19200 bps 초과 속도에서는 Modbus 규격대로 t3.5 = 1.75 ms로 고정합니다.
3. 응답 송신: 하드웨어 DE로 송신합니다. 송신 완료(`TC`) 후 `bl_run_requested()`를 확인해 앱으로 점프합니다.
4. 점프 루틴(개념):
   ```c
   __disable_irq();
   /* SysTick, USART, 클록 등 부트로더가 켠 주변장치 원복 */
   SCB->VTOR = APP_ADDR;                 /* 0x08008200 */
   __set_MSP(*(uint32_t *)APP_ADDR);
   ((void (*)(void))(*(uint32_t *)(APP_ADDR + 4)))();
   ```
5. 링커 스크립트: 부트로더는 `FLASH ORIGIN=0x08000000 LENGTH=32K`, 앱은 `ORIGIN=0x08008200`에서 시작하고 설정·교정 영역 전까지만 씁니다.
6. 빌드 후 `mkimage`로 `.oiw`를 생성하는 단계를 CI에 추가합니다.
